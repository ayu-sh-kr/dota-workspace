# Dota SSR

`@ayu-sh-kr/dota-ssr` adds opt-in build-time static generation and client hydration to Dota applications.
The browser entry exports `dotaHydration()`, while `@ayu-sh-kr/dota-ssr/vite` exports the build-only
`dotaSsg()` plugin. Without either extension, Dota Core, Rendering, Router, and Wrap retain their
existing client-render behavior.

```ts
import {dotaHydration} from '@ayu-sh-kr/dota-ssr';

initializeApp({
  ...config,
  plugins: [dotaHydration()]
});
```

```ts
import dotaSsg from '@ayu-sh-kr/dota-ssr/vite';

export default defineConfig({
  plugins: [dotaSsg({autoDetectRoutes: true})]
});
```

Mark a concrete page route with `ssr: true` to include it in autodetection. Routes remain client-only
by default, and explicit `routes` can still be supplied to add routes or override an autogenerated
route's output file.

```ts
@Route({path: '/blogs', ssr: true})
export class BlogPage extends DotaPageElement {}
```

The application entry must export an `applicationReady` promise. The Vite plugin waits for it,
waits for happy-dom's pending work, renders every configured route in a fresh window, and writes
route-specific HTML below Vite's output directory. Use the optional `settle` callback when a static
route has an additional application-specific data-readiness barrier.

Vercel routing updates are opt-in. Set `vercel: true` to update the nearest `vercel.json` with
redirects from generated route paths to their static output documents while preserving other
configuration. Pass `{vercel: {configFile: '../vercel.json'}}` when the project configuration
cannot be discovered above the Vite root.
